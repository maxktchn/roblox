# Gear Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Players own, equip, level, merge and salvage gear between runs; equipped gear makes the next run stronger, and Epic/Legendary items add bonus effects.

**Architecture:** Gear numbers live in `Config/Gear.luau`. A shared `GearMath` module does every gear calculation, so the server and the Gear screen always agree. `GearService` is the only owner of `Data.Gear` and `Data.Currencies`. It checks every action from the `GearAction` remote, sends the client a `GearState` snapshot, and at the start of each run fixes the "run gear" and hands its bonuses to `StatsService`. `GearEffectsService` reads the run gear and turns on the bonus effects through small hooks in `WeaponService`, `RunManager`, `StatsService` and `UpgradeService`.

**Tech Stack:** Luau `--!strict`, Rojo, ProfileStore through `DataService` (P2-1).

**Spec:** `docs/superpowers/specs/2026-11-17-gear-design.md` (issues #136 to #139)

## Global Constraints
- Items: `ChefsKnife`, `FryingPan`, `RollingPin` (slot Utensil, names from `Starters.luau`); `ChefsHat` "Chef's Hat" (Hat); `Apron` "Apron" (Apron); `OvenMitts` "Oven Mitts" (Mitts); `Shoes` "Shoes" (Shoes). Main stat and material per slot come from `Gear.Slots` (already in config).
- Stat tables (bonus as a fraction, Lv 1 → max level, a straight line between):
  - Attack: Common 0.02→0.05, Fine 0.08→0.14, Rare 0.16→0.26, Epic 0.30→0.42, Legendary 0.48→0.60
  - Hp: Common 0.03→0.07, Fine 0.10→0.18, Rare 0.20→0.33, Epic 0.38→0.52, Legendary 0.60→0.75
- Gear is a separate multiplier: damage × (1 + sum of run gear Attack) × (1 + ingredient Damage); max HP = `RunRules.ChefMaxHp` × (1 + sum of run gear Hp) × (1 + ingredient MaxHp).
- Gear is fixed when a run starts ("run gear"). Changing gear never changes the current run.
- Level cost for Lv L → L+1: gold `math.round(LevelCost.Gold * Growth^(L-1))`, material `math.ceil(LevelCost.Material * Growth^(L-1))`. Starting values `Gold = 100`, `Material = 1`, `Growth = 1.08` (placeholders until #106).
- Merge: 3 distinct copies, same item, same rarity, not Legendary → 1 copy at the next rarity, Lv 1. Refund `math.floor(0.8 × spent)` of the 3 copies' `SpentGold` and `SpentMaterial` (`Gear.SalvageRefund`). If one of the 3 was equipped, the new item is equipped.
- Salvage: gold `SalvageGold[rarity] + floor(0.8 × SpentGold)`, material `1 + floor(0.8 × SpentMaterial)`. `SalvageGold` placeholders: Common 20, Fine 60, Rare 180, Epic 540, Legendary 1620. Refused for the equipped item and for the player's last `ChefsKnife`.
- Save layout: `Gear = { NextId = number, Items = { [string id] = { Item, Rarity, Level, SpentGold, SpentMaterial } }, Equipped = { [slot] = string id } }`; `Currencies = { Gold, Sharpener, HatPattern, ApronPattern, MittPattern, ShoePattern }` (all numbers). Item ids are strings. Save `Version` stays 1.
- Gear actions are only allowed between runs (`RunManager.isRunOver()`).
- Bonus effect numbers (Epic / Legendary) live in each item's config entry:
  - ChefsKnife: second knife every 5 / every 3 attacks
  - ChefsHat: 1 / 2 free "Order Up!" picks at run start
  - Apron: blocks a hit every 12 s / 7 s
  - OvenMitts: 10% / 20% of hits burn (5 dps for 3 s); Legendary spreads the fire on death
  - Shoes: +30% walk speed for 2 s after a hit; Legendary also 1 s of no damage
  - FryingPan: stun 0.5 s / 1 s + spread. RollingPin: slow 30% / 50% for 2 s, Legendary +20% damage taken. These are config only; #107 builds them.
- Project rules (CLAUDE.md): every file starts `--!strict`; stylua, selene, rojo build and luau-lsp clean; server authority, so every remote argument is checked; config cross-references go in `ConfigCheck`; a config number change updates the PRD.

## Review Focus
- **The same copy sent three times in a Merge** (`{"5","5","5"}`), or an id that isn't the player's: refused, nothing changes. Tested in Task 3 (`merge needs 3 different copies`, `someone else's id`).
- **A save reload mid-run** (`DataService.reload`, or the first load arriving after the first run started): run gear and the Hat's free picks are applied once per run, not again. Tested in Task 2 (`first run gets gear once`) and Task 5 (`hat picks once per run`).
- **`Equipped` pointing at an item that no longer exists** (a hand-edited or half-reset save): treated as empty, and the free knife fix-up re-equips a knife in Utensil. Tested in Task 2 (`broken equipped repaired`).
- **Saving off (`SaveStatus` Off):** gear works in memory and nothing is written. Tested in Task 3 (`off: actions work in memory`).
- **Bad remote arguments** (numbers instead of strings, a 2-item merge list, unknown action, actions mid-run): ignored or refused with a message, never an error. Tested in Task 3 (`bad arguments refused`, `mid-run refused`).

## How tests run here
No test framework. Tests are Luau scripts run through the Studio MCP in dev.rbxl, with Rojo serving this branch. Check which Studio Rojo is syncing first. Pure `GearMath` checks run in the Edit context (`require(game.ReplicatedStorage.Shared.GearMath)`). Service checks inject a Script into ServerScriptService during play, so it shares the module cache. The Script writes `PASS name` / `FAIL name (detail)` lines to a workspace attribute, and the runner polls for it, as in `scratchpad/save_t2.lua`. The scripts live in the scratchpad (`gear_t<N>.lua`) and aren't committed. Restart play after code changes. After each task: `stylua src`, then `check.sh` → `RESULT: PASS`.
